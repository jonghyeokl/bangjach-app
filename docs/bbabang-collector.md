# 빠방 테스트 데이터 수집

범위: **홈 → 전국 / 예약 가능 해제 / 안 한 테마 해제 / 추천도 높은 순**, 광고 슬롯 제외 상위 **30개**.

테마명·카페명·사진·제한 시간(분)·소개·홈페이지를 저장한다. ‘추천수 많은 순’과 다르다. 동점 항목도 응답 순서를 그대로 유지하며 별도로 재정렬하지 않는다. 홈 화면 기본 조건인 영업 중인 테마/카페만 포함하며, 별도로 삽입하는 광고 응답(`selectAd`)은 읽지 않는다. 광고주 테마가 일반 검색 순위에도 있으면 일반 항목으로는 포함한다.

## 실행

앱 저장소에서:

```sh
source ../dev-env.sh
npm run collect:bbabang
```

1. 출력된 `collector.js` 파일을 연다.
2. **빠방이 정상적으로 검색되는 Chrome**에서 개발자 도구 → Sources → Snippets → New snippet에 파일 내용을 넣고 실행한다. 사이트를 새로고침하면 수집기는 해제된다.
3. 전국을 선택하고 ‘예약 가능’·‘안 한 테마’를 끈다. 정렬을 다른 항목으로 바꿨다가 **추천도 높은 순**으로 바꾼다.
4. 수집 완료 안내의 **30개 JSON 저장**을 누른다.
5. 내려받은 JSON을 사용해 CSV와 사진 파일을 저장한다.

```sh
npm run collect:bbabang -- --input ~/Downloads/bbabang-top30.json
```

사진 파일 없이 JSON·CSV만 필요하면 `--no-images`, 저장 위치를 지정하려면 `--output /원하는/폴더`를 붙인다.

```text
test-data/bbabang/<실행 시각>/
├── themes.json       # 수집 시각·필터·순위·원본 누락·사진 실패 내역 포함
├── themes.csv        # UTF-8 BOM, 소개 줄바꿈 유지
└── images/           # 01-테마ID.jpg/png/webp ...
```

## 제한과 확인 범위

- 독립 자동화 브라우저의 검색은 실제 점검에서 **App Check 401**로 거절됐다. 그래서 일반 브라우저가 정상적으로 보내는 검색 요청에서만 작동한다. App Check/로그인/차단을 우회하지 않으며 인증값은 출력·파일에 저장하지 않는다.
- 수집기는 정확한 검색 조건일 때 **요청 개수만 30으로 변경**한다. 응답을 읽은 뒤 원래 `fetch`를 복구한다. 나머지 요청과 광고 요청은 그대로 통과시킨다.
- 사이트가 거절하거나 응답 형식·정렬이 바뀌거나 30개가 안 되면 성공 파일을 만들지 않는다. 해당 안내를 확인하고 정상 검색 상태에서 다시 실행한다.
- 원본이 빈 소개/홈페이지/사진은 추측하지 않고 `missing_fields`에 기록한다. 사진 다운로드 실패도 표시하며 원래 URL을 보존한다. 사진 요청은 순차적으로 0.5초 간격, 30초 제한, 12MB 이하로 처리한다.
- 수집 결과와 사진은 Git에서 제외한다. 앱·운영 DB에는 자동으로 넣지 않는다.
- 테스트: `npm run test:collector`. 조건·순위·중복·30개 제한·CSV·사진 다운로드 실패·브라우저 요청 보존을 가상 데이터로 확인한다. 실제 30개 수집 여부와 가상 테스트 결과는 구분한다.
