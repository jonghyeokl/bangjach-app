# 빠방 테스트 데이터 수집

범위: **홈 → 전국 / 예약 가능 해제 / 안 한 테마 해제 / 추천도 높은 순**, 광고 슬롯 제외 상위 **200개**.

테마명·카페명·사진·제한 시간(분)·소개·홈페이지와 DB 등록에 필요한 카페 지역·주소·전화번호를 저장한다. ‘추천수 많은 순’과 다르다. 동점 항목도 응답 순서를 그대로 유지하며 별도로 재정렬하지 않는다. 홈 화면 기본 조건인 영업 중인 테마/카페만 포함하며, 별도로 삽입하는 광고 응답(`selectAd`)은 읽지 않는다. 광고주 테마가 일반 검색 순위에도 있으면 일반 항목으로는 포함한다.

## 실행

앱 저장소에서:

```sh
source ../dev-env.sh
npm run collect:bbabang
```

1. 출력된 `collector.js` 파일을 연다.
2. **빠방이 정상적으로 검색되는 Chrome**에서 개발자 도구 → Sources → Snippets → New snippet에 파일 내용을 넣고 실행한다. 이전 수집기를 실행했다면 먼저 사이트를 새로고침한 뒤 새 스크립트로 교체·실행한다.
3. 전국을 선택하고 ‘예약 가능’·‘안 한 테마’를 끈다. 정렬을 다른 항목으로 바꿨다가 **추천도 높은 순**으로 바꾼다.
4. 수집 완료 안내의 **200개 JSON 저장**을 누른다.
5. 내려받은 JSON을 사용해 CSV와 사진 파일을 저장한다.

```sh
npm run collect:bbabang -- --input ~/Downloads/bbabang-top200.json
```

사진 파일 없이 JSON·CSV만 필요하면 `--no-images`, 저장 위치를 지정하려면 `--output /원하는/폴더`를 붙인다.

```text
test-data/bbabang/<실행 시각>/
├── themes.json       # 수집 시각·필터·순위·원본 누락·사진 실패 내역 포함
├── themes.csv        # UTF-8 BOM, 소개 줄바꿈 유지
└── images/           # 01-테마ID.jpg/png/webp ...
```

## 제한과 확인 범위

- 독립 자동화 브라우저의 검색은 실제 점검에서 **App Check 401**로 거절됐다. 그래서 일반 브라우저가 정상적으로 보내는 검색 요청에서만 작동한다. App Check/로그인/차단을 우회하지 않으며 인증값은 출력·파일에 저장하지 않는다.
- 수집기는 정확한 검색 조건일 때 **요청 개수만 200으로 변경**한다. 응답을 읽은 뒤 원래 `fetch`를 복구한다. 나머지 요청과 광고 요청은 그대로 통과시킨다.
- 사이트가 거절하거나 응답 형식·정렬이 바뀌거나 200개가 안 되면 성공 파일을 만들지 않는다. 해당 안내를 확인하고 정상 검색 상태에서 다시 실행한다.
- 원본이 빈 소개/홈페이지/사진은 추측하지 않고 `missing_fields`에 기록한다. 사진 다운로드 실패도 표시하며 원래 URL을 보존한다. 사진 요청은 순차적으로 0.5초 간격, 30초 제한, 12MB 이하로 처리한다.
- 수집 결과와 사진은 Git에서 제외한다. 앱·운영 DB에는 자동으로 넣지 않는다.
- 테스트: `npm run test:collector`. 조건·순위·중복·200개 제한·CSV·사진 다운로드 실패·브라우저 요청 보존을 가상 데이터로 확인한다. 실제 200개 수집 여부와 가상 테스트 결과는 구분한다.

## 실제 데이터 검증 (2026-11-02)

기존 30개 수집 당시 사용자가 일반 브라우저에서 저장한 JSON으로 실제 내보내기를 완료했다. 200개 실제 수집은 새 스크립트 실행 후 확인해야 한다.

- 요청한 조건의 30개 테마·25개 카페, 필수 수집 항목 누락 없음.
- 사진 30장(PNG 16장·JPEG 14장) 다운로드 및 이미지 디코더 검증 완료.
- CSV 30행, 소개 줄바꿈과 원본 JSON의 6개 수집 항목 일치 확인.
- 로컬 결과: `test-data/bbabang/top30-20261102/`의 `themes.json`, `themes.csv`, `images/`.
- 이 검증 당시의 결과 파일은 Git에서 제외했으며 운영 DB에는 입력하지 않았다.

## 사진 처리부터 DB 등록까지 한 번에

카페 필수 정보와 200개 수집이 적용된 **새 수집 스크립트**로 JSON을 다시 저장한다. 기존 JSON에는 지역·주소·전화번호가 없어 새 카페를 등록할 수 없다.

백엔드 `.env`의 DB에 연결할 수 있어야 한다. Cloud SQL Proxy를 쓰는 현재 설정에서는 먼저 별도 터미널에서 실행해둔다.

```sh
cloud-sql-proxy --port 5433 bangjach-api:asia-northeast3:bangjach-postgresql
```

앱 저장소에서 **다운로드·CSV 생성·등록 미리보기**:

```sh
npm run collect:bbabang -- --input ~/Downloads/bbabang-top200.json --import-db
```

**다운로드부터 실제 등록까지**:

```sh
npm run collect:bbabang -- --input ~/Downloads/bbabang-top200.json --import-db --apply --photo-bucket bangjach-api-192693215385-review-photos
```

- 백엔드 저장소는 기본적으로 앱 저장소 옆의 `bangjach`를 사용한다. 다른 위치면 `--backend /백엔드/경로`로 지정한다. 백엔드 `.venv`와 DB 마이그레이션이 준비되어 있어야 한다.
- 사진은 원본을 로컬에 보관하고, DB 등록 시 긴 변 1600px 이하 JPEG로 축소·EXIF 제거 후 서비스의 사진 버킷에 저장한다. API의 일반 사진 업로드 제한은 변경하지 않는다.
- 같은 원본 테마 ID는 다시 만들지 않는다. 기존 카페·테마는 이름도 비교하며, 기존 내용을 자동 덮어쓰지 않는다. 같은 카페명인데 주소가 다르거나 이름이 중복되면 중단한다.
- 원본 추천도·리뷰 수는 순위 검증용이다. 방자취 사용자 평점이나 리뷰로 넣지 않는다.
- 누락·잘못된 사진은 DB에 쓰기 전에 검사한다. 등록 중 실패하면 DB 변경을 취소하고 이번에 올린 사진도 정리한다. 결과는 출력 폴더의 `import-report.json`에 저장한다.
- 이미 사진을 내려받았다면 다시 다운로드하지 않고 백엔드에서 `.venv/bin/python -m app.jobs.import_bbabang /수집폴더/themes.json --apply --photo-bucket bangjach-api-192693215385-review-photos`로 등록할 수 있다.
- 지역·주소·전화번호가 원본에도 없으면 임의 값을 넣지 않고 중단한다. 누락된 정보를 보완해야 한다.

검증: 별도 PostgreSQL에서 미리보기 무변경, 등록·재실행·동시 실행 중복 방지, 사진 조회, 필수 정보 누락/저장 실패 시 롤백, 고해상도 사진 축소를 확인했다. 실제 운영 데이터 등록은 새 JSON 수집 후 실행한다.
